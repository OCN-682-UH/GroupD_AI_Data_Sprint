# OPIHI Project Reflections


### Mei Iwamoto
For this project, I helped to clean the OPIHI 2024, 2019, and 2020 data files to prep them for the master file. After Kat joined all the datasets together into one master file, I used that to create a figure that looked at sampling consistency of different schools/teams to answer our research question for this project. Finally, I helped to write the AI developer log using AI usage examples from my own cleaning script I made when cleaning said data files above. 

It was my first time using AI on this scale for a project - I found it very helpful for this project specifically, where we had multiple decades of data in a variety of different formats and collected by different groups of individuals. I used Gemini to help join this data across different formats and I think it was really helpful for tedious tasks like that. All AI-generated outputs were checked for any errors and any sensitive information such as school names or teacher names were redacted and recoded prior to uploading data to AI. 

I did notice you had to be very specific in asking AI what you wanted, and there were multiple times where an initial output was not up to par because I wasnʻt specific enough in my prompts and I had to ask Gemini to redo it with more specific commands. This was especially the case with some of the datasheets that were less organized, with different tables or formats all within the same sheet. I often had to ask Gemini to ignore all rows past a certain one to help exclude said tables or extra rows of unneeded calculations. 

Overall, I think I would use Gemini again for tedious tasks in the future, with the caveat that I check all the outputs it makes throughly, and redact any sensitive information. I do think I would only use Gemini for tedious things and try to do most things manually on my own because I am still learning how to use R and want to get a lot of practice on my own first!

### Kat Viehl
For the AI data sprint project, each of us took on a subset of the years to reformat. I helped reformat and clean the 2004, 2005, 2008, and 2026 datasets, and then I helped join all four of our fixed subsets together to create the master sheet. Afterwards, I collapsed redundant columns in the master sheet and cleaned up the data, standardizing organism/place names, separating columns that had too much information, reformatting columns that had varying ways of displaying data (e.g. the date column), created the data dictionary, and struggled a lot with AI. 

I felt like AI was an incredible tool at times, quickly spitting out a code that would've taken me weeks to learn to write by myself. However, the code it spit out was often incomprehensible to me or took a long time for me to understand. Granted, most of the time I did ask it to do a lot all at once. It created errors a few times, so I kept those logs in my script to show the troubles. I found myself just going right back to it if errors occurred instead of trying to figure it out myself, which made me feel uncomfortable with how easy it is to lean on. As for personal verification, I kept a separate copy of all the files (with names and locations redacted or switched) for testing before use on the real files, which was very useful to confirm that the scripts it generated worked at all. This caused a disruption in my typical method of file organization, leaving me with several copies of test files, which I did not like at all. I always cross-checked the data with the previous files, but since this dataset was quite large, I had to cherry-pick random rows to see how it went. I often used the count() function to see how columns changed throughout the process. If it made a small error somewhere, it would be hard for me to find it since the AI generated code is not well annotated and difficult to read.
